# Èffort Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Trasformare Dieta in Èffort, app unica per dieta e allenamento, con importazione dei dati di Palestra.

**Architecture:** Si evolve il target `Dieta` esistente mantenendo bundle ID e file `dieta.json`. Il codice di Palestra si porta dentro questo progetto solo dove serve; la logica nuova sta in file piccoli e testabili senza SwiftUI, le viste leggono la palette dall'ambiente.

**Tech Stack:** Swift 5, SwiftUI, Observation, XCTest, Xcode 26+. Nessuna dipendenza esterna.

**Spec:** `docs/superpowers/specs/2026-10-31-app-unica-design.md`

## Global Constraints

- iOS 18 o successivo, solo iPhone. Bundle ID `io.github.aspirinag.dieta`, file dati `dieta.json`.
- Nome visibile `èffort`, sempre minuscolo con l'accento; nomi tecnici e file `Effort`.
- Nessun server, nessuna dipendenza esterna, nessun dato cancellato durante la migrazione.
- Il formato JSON cresce solo aggiungendo campi, letti con `c.valore(...)`.
- Font: Georgia in tutta l'app, numeri compresi, salvo gli elementi di sistema che iOS non lascia cambiare. Gli helper di font restano in un punto solo e rispettano il testo grande.
- Contrasto minimo 4.5:1, tasti di almeno 44 punti, testo grande di iOS supportato.
- Tutti i testi in italiano. Nomi: Misurazioni, Progressi, Allenamento, Piano alimentare, Inverti le settimane.
- Test: `xcodebuild test -project iOS/Dieta.xcodeproj -scheme Dieta -destination 'platform=iOS Simulator,name=iPhone 18 Pro' CODE_SIGNING_ALLOWED=NO`.
- Non si fa push né merge su `main` senza un sì esplicito: `main` pubblica la release.
- Versioni: ogni tappa aggiorna `MARKETING_VERSION` con `scripts/versione.sh` e scrive le sue voci in `CHANGELOG.md`, in italiano e per chi usa l'app.

## Review Focus

- Nuova installazione chiusa prima di creare un profilo: un salvataggio con zero profili non deve rendere illeggibile il file al riavvio.
- Backup di Palestra importato due volte, o importato con un allenamento già presente nello stesso giorno: nessun duplicato e nessuna perdita.
- App chiusa o riavviata a metà allenamento, oppure lasciata aperta oltre la mezzanotte: l'allenamento riprende e resta legato al giorno di inizio.
- Backup di Dieta già esistenti, con Alessandra e senza campi nuovi: si aprono identici e la prima apertura non compare.
- Kg o ripetizioni vuoti, zero o con la virgola sulla spunta: la serie non si salva con valori non validi e nessun NaN arriva al file.
- Tocco sbagliato su «Mangiato» o sulla spunta, annullato dopo il salvataggio: il file torna identico e il recupero si ferma.
- Due esercizi uniti in uno che compare due volte nello stesso allenamento o nella stessa routine: nessuna serie persa, record e precedenti calcolati sul nome unico.
